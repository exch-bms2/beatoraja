# タイマーがオフのオブジェクトの描画条件を省略する

既定で有効です。`-Dbeatoraja.skin.skipDrawWhenTimerOff=false`（Gradleでは `-PskipDrawWhenTimerOff=false`）で無効にでき、その場合はすべての描画条件を毎フレーム評価する従来の動作に戻ります。

## 何をするか

スキンのオブジェクトは、描画条件（`draw`）が真で、かつタイマー（`timer`）がオンのときに描画されます。従来は、描画条件を先に評価し、真のときだけタイマーを見ていました。

この機能では、**タイマーが確実にオフである**と、状態を変えずに判定できる場合に限り、描画条件を評価せずに非表示とします。
タイマーがオフなら、描画条件がどの値を返しても描画されないため、表示の結果は同じです。

「確実にオフ」と判定するのは次のタイマーです（`TimerProperty.isDefinitelyOff`）。

| タイマー | 判定 |
| --- | --- |
| 番号で指定する組み込みタイマー（JSON/LR2スキンの `timer = 41` など） | タイマーがオフ |
| `timer_util.timer_observe_boolean(f)` | タイマーの状態がオフで、かつ今 `f()` が false（このとき評価してもオフのまま） |
| `timer_util.timer_function(id)`、`new_passive_timer()` のタイマー | 値がオフ |
| 上記以外のLua関数のタイマー | 判定しない（従来どおり評価する） |

ModernChicの選曲画面では、閉じているサイドメニューの描画条件190回/フレームが0回になりました。Lua時間は229.9 µsから170.1 µsに減っています（各1回ずつの実機計測）。

## 省略しない描画条件

描画条件の中で状態を更新するスキンがあります。インストール済みスキンの描画関数2,850個のうち15個がこれに当たります。
例：WMII_FHDの `delayTime = delayTime + 1`、ModernChicのリザルト画面の `isInfoMenu1 = true`。

これらは毎フレーム実行され続ける必要があります。そこで、Luaの描画関数のバイトコードに、自分のローカル変数以外への代入（`SETUPVAL` / `SETTABUP` / `SETTABLE` / `SETLIST`）が1つでもあれば、省略しません（`BooleanProperty.hasNoSideEffects`）。
`timer_observe_boolean` の `f` にも同じ確認を行い、代入を含む `f` のタイマーは「確実にオフ」の判定に使いません。

## 振る舞いが変わり得るケース（既知のリスク）

1. **描画条件や `f` から呼ぶ別の関数に副作用がある場合**
   代入の確認は、その関数自身のバイトコードだけを対象にしています。`draw = function() update() return true end` のように呼び出し先で状態を更新していると、検出できません。
   その場合、タイマーがオフの間は `update()` が呼ばれなくなります。また、判定のために `f` が1回余分に呼ばれます。
2. **同じフレームの中で `f` の結果が変わる場合**
   `f` が乱数などで呼ぶたびに結果を変えると、タイマーがオンになるのが1フレーム遅れることがあります。
3. **非表示のオブジェクトの内部状態**
   非表示の間は、位置・色・角度の計算（`prepare` の後半）を行いません。これらは表示されたフレームで計算し直されます。
   従来は非表示の間も、位置にオフセットが毎フレーム加算されていましたが、それも起きなくなります。

スキンの表示や動きが変わった場合は、`-PskipDrawWhenTimerOff=false` で無効にして比べてください。

## テスト

`SkipDrawWhenTimerOffTest`（`./gradlew regressionSkipDrawWhenTimerOffTest`）で次を確認しています。
- タイマーの状態、判定できるかどうか、副作用の有無、描画条件の値のすべての組み合わせで、表示の結果が省略しない場合と同じになること。省略するのは安全な場合だけであること。
- `timer_observe_boolean` がオフ→オン→オフと遷移すること。
- `f` に副作用がある場合は判定しないこと。
- 受動タイマーと、任意のLuaタイマーの扱い。
- 描画条件の副作用の判定。
