# 未登録プロパティIDの結果をキャッシュ

2026-11-25。整数・画像インデックス・真偽値の数値ID検索は、登録済みIDの結果だけをキャッシュしていた。未登録IDは毎回範囲とenumを検索し、values()の配列も繰り返し確保していた。

未登録IDをboolean配列で記憶し、2回目以降はnullを返す。登録済みプロパティのキャッシュを先に確認する従来の経路は維持する。真偽値では正のIDと否定形の負のIDが未登録の結果を共有する。工場の定義は固定で、実行中に登録を追加する公開APIはない。

配列3本で約192 KiBの固定メモリが増える。初回の未登録IDの検索には従来の処理が必要。プロパティの値や未知IDのフォールバック値は変更しない。

## 検証

PropertyIdCacheTestで全65536 IDの整数・画像・正負の真偽値の登録有無と、繰り返し検索での同一性を確認。変更前のクラスに差し替えて同じテストを実行し、登録有無のSHA-256が変更後と一致した。整数の範囲外ID、真偽値の±65536なども確認。BooleanPropertyFactoryのInteger.MIN_VALUEに対する既存挙動は本変更の対象外。

PropertyIdCacheTest、StringPropertyLookupTest、PropertyNameCacheTest、MainStateInputLuaApiTest、SkinCompatibilityApiTest、SkipDrawWhenTimerOffTestの6件が成功。

## JMH

JDK 17.0.19 arm64、JMH 1.37、各測定2 forks、warmup 2×500ms、measurement 3×500ms、ヒープ512 MiB、-prof gc。A1（旧）→B1（新）→B2（新）→A2（旧）の順。旧ファクトリのクラスを保存して同じクラスパスの先頭で差し替えた。以下は各2測定のスコアの単純平均。

登録済みの整数は74、画像は303、真偽値は1008と-1008。未登録は65535と-65535。いずれもウォームアップでキャッシュ済みの状態を測った。短いマイクロベンチマークで、Lua VMとフレーム全体は測定していない。

## 実スキンへの効果の範囲

ModernChicとWMII_FHDのmain_state.number/optionに直接書かれた数値リテラル39種類を、行コメントを除いて調べた範囲では、未登録IDは見つからなかった。この簡易走査は定数参照や計算で作るIDを対象にしない。実スキンで未登録IDが頻出する証拠はまだなく、画面全体の速度向上は未確認。

未対応のIDを毎フレーム読む互換スキンなどで有効な変更であり、全スキンが大きく速くなるとは評価しない。実行ソースと生データは missing-property-cache-performance.json に保存。
